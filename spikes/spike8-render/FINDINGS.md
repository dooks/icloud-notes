# Spike 8: decoded note body → sanitized HTML (2026-10-25)

**Verdict: it works.** All 240 inline note bodies from spike 2's saved pages render to HTML, and every page has
properly nested tags (checked by `balanced()`), with no decode failures. The user compared notes 133, 162, 192 and 87
against Apple Notes and reported that they **look right**.
The renderer is about 450 lines of plain Rust with no HTML or sanitizer crates. Every tag is generated by our own code, and
note text and attribute values are always escaped.

## What was built
- Crate: `spikes\spike8-render\` (cargo only, offline). `src\decode.rs`, `build.rs` and `vendor\` are **copied** from spike 3
  instead of linked by path, because spike 3 was still being edited. Same crate versions: prost 0.14.4, protox 0.10.0.
- `src\render.rs`: runs → paragraphs → HTML, sanitizing, standalone page wrapper with a CSP, and a tag-balance check.
  Covered by 12 tests.
- `src\main.rs`: commands `stats`, `list` and `render <idx,..> [--debug]`. The input defaults to
  `..\spike2-cloudkit\out`. A recordName that appears again on a later page replaces the earlier copy.

```
cargo test                                  # 15 tests (3 decode + 12 render/sanitize)
cargo run -- stats                          # content-free feature counts
cargo run -- list                           # content-free list -> out\list.txt + suggested picks
cargo run -- render 133,162 --debug         # out\note-133.html (+ -debug.html); contains note text
```

## Rendering model
1. **Spans** come from spike 3's `spans()` and are measured in UTF-16 units. A run that ends in the middle of an emoji
   (a surrogate pair) produces U+FFFD instead of crashing. This never happened on real data; it is tested only on a
   made-up note.
2. **Paragraphs:** the spans are split at `\n`. Paragraph attributes (style, indent, alignment, quote, checklist) come
   from the run that holds the paragraph's `\n`. If the last paragraph has no `\n`, they come from its last run.
   **Check: in 0 paragraphs did runs disagree on paragraph attributes**, so the rule is safe on this data.
3. **Blocks:** title → `h1`, heading → `h2`, subheading → `h3`, body → `p`, and an empty paragraph → `<p><br></p>`.
   Consecutive monospaced paragraphs become one `<pre>`, and consecutive quote paragraphs become one `<blockquote>`.
4. **Lists:** consecutive list paragraphs become nested `ul`/`ol` by `indent_amount`, with each nested list inside the
   previous `<li>`. A change of list type at the same level closes the list and opens a new one. Depth is capped at 8.
   If a list starts deeper than level 0, empty `li.nest` wrappers are added above it.
   Numbering is left to the browser's `<ol>`, and it matched in the notes checked.
5. **Inline:** within a paragraph, consecutive runs with the same link share one `<a>`. Inside it come
   `b`/`i`/`u`/`s`/`sup`/`sub`, then `mark.emN`, then `span style=color`.
6. **Attachments:** `<span class="att" data-kind data-uti data-id>[kind]</span>`. The kind comes from the UTI:
   table, drawing, sketch (com.apple.paper), image, calculation, inline, link-card, video, audio, pdf, or attachment.
   Real attachment handling is spike 5's job.

## Sanitization (for a Tauri webview)
Model: **generate, don't filter.** The note format is structured data, so no markup from the note ever reaches the page.
Each rule below has a test.
- **Text nodes:** `& < > " '` are escaped. These are removed: C0/C1 control characters except `\t` (including `\r`), the
  bidi controls U+202A–202E and U+2066–2069 (to block spoofing such as reversed URLs), and any U+FFFC outside an
  attachment run. U+2028/2029 become `<br>`. Real data needed none of this except the 10 U+2028s.
- **Attributes** (href, title, data-*): escaped the same way, with control characters dropped. Attachment `data-id` must be
  `[A-Za-z0-9-]{1,64}` and `data-uti` must be `[A-Za-z0-9.-]{1,128}`; otherwise they're omitted.
- **Links:** the scheme is computed the way a browser does it: leading whitespace and controls trimmed, embedded tab/CR/LF
  removed, then lowercased. Only `http`, `https` and `mailto` with no control characters become
  `<a href rel="noopener noreferrer">`. Everything else becomes a dotted-underline `<span>`: `javascript:`, `data:`,
  `file:`, relative URLs, `applenotes:`, and `tel:` (could be added later).
  **In the app:** never let the webview navigate. Intercept clicks (Tauri `on_navigation` returning false, or a click
  handler) and pass http/https/mailto to the OS opener after checking them again.
- **Colour:** only the generated value `rgba(r,g,b,a)` from clamped floats, with NaN → 0 and an alpha floor of 0.3 so
  text can't be hidden. This is the only inline `style` attribute. Everything else uses classes.
- **Depth and size limits:** list and indent depth are capped at 8. The largest page is 80 KB (from the largest note,
  72k UTF-16 units). No length limit is needed for these notes. A real app could add a cap, say 2 MB, as a safety net.
- **Test files:** each standalone page carries the CSP `default-src 'none'; style-src 'unsafe-inline'`, so it can't run
  scripts or load anything.
- **Recommendations for Tauri:**
  - Show note HTML in a view with **no IPC capability**: a separate window/webview without capabilities, or a
    `sandbox` iframe (`srcdoc`, no `allow-scripts`) inside the app's own UI.
  - App CSP: `default-src 'none'; style-src 'self'; style-src-attr 'unsafe-inline'; img-src <attachment scheme only>`.
    `style-src-attr` is needed only for colour. To remove it, map colours to a fixed palette of classes, since only one
    colour occurs here.
  - Never use `innerHTML` with untrusted strings in the app's own JS. The Rust side returns a complete fragment, which is
    inserted as-is into the sandboxed frame.
  - Attachment images (spike 5) should be served from a custom protocol (`notes-asset://<id>`) that resolves only IDs
    from our own database, never URLs taken from the note.

## Open issues
1. **ParagraphStyle.7** (76 paragraphs): 38 on numbered items, 26 on bullets, 12 on body. On numbered items it equals the
   item's position in its list 35 times, differs 3 times, and is missing on 111 items. Values: 1 (58), 2 (7), 4 (8),
   3/5/6 (1 each). It may be a list start number or a "continue numbering" hint. The browser's own numbering matched
   in the notes checked, but a list that continues numbering across interruptions could still be wrong. To settle it,
   make a test note on the phone with a list that is interrupted and then continued.
2. **Style 3** (7 paragraphs in 2 notes) is rendered as body. The user saw nothing wrong in note 87, but no one
   checked specifically what Notes shows for those paragraphs.
3. **Checklists, quotes, highlights and super/subscript** have no real examples in this account. The code paths are
   tested only on made-up notes. The `emphasis_style` value → colour mapping (iOS 18 highlight colours) is unknown.
4. **Dark mode:** an explicit dark text colour (#333333) is hard to read on a dark background. Options: drop colours
   close to the default text colour, or adjust lightness in dark mode.
5. **Font sizes** (pasted text) are ignored. That matches Notes' default look closely enough for now.
6. **Attachments** are markers only: tables (30) need the MergableDataProto renderer, and images and drawings need
   spike 5's asset fetching. The `calculateresult` and hashtag inline attachments need their text from InlineAttachment
   records.
7. **The note with `TextDataAsset`** (body stored as a separate asset) isn't covered: there is no inline body to render.
   Once downloaded, it goes through the same pipeline.
8. **Title handling:** the title is the first paragraph (`h1`) in the body. `TitleEncrypted` is used only for the
   page's `<title>`. Some notes have several title-styled paragraphs, which render as several `<h1>`s and looked right.
9. **Deleted notes:** none of the 240 had `Deleted` set, so how they should be filtered isn't checked here.

## Privacy
`stats` and `list` print no note content: only indexes, modification dates, lengths, feature codes, UTIs, link schemes
and colour values. `out\` (list.txt and the rendered `note-*.html`, which do contain note text) is ignored by
`.gitignore` and should be deleted when no longer needed.
